# Sessão 25b: pessoas — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** e-mail pessoal, telefone com máscara e copiar, saída só com Inativo + motivo, período de trainee, 3 cursos fixos e correção do participante que some na equipe.

**Architecture:** Backend ganha três colunas em `usuarios` (migração 022), perde o status `alumni` (o tipo `status_pessoa` é recriado) e passa a aceitar só 3 cursos (CHECK no banco + regra no caso de uso, conferida só quando o campo muda). Front: cálculos puros em `src/lib/pessoaContato.js` e `src/lib/periodos.js`, telas Pessoas, Perfil e `AreasPessoa` ajustadas; o bug da equipe é reproduzido antes de corrigir.

**Tech Stack:** Express + TypeScript + `pg` (back, Jest); React 18 + Vite + Vitest (front); Playwright (e2e, fora das dependências).

**Spec:** `docs/superpowers/specs/2026-11-19-conta-pessoas-design.md`, seção 7 (e 2, 3, 8, 9).

## Global Constraints
- Migração única: `migrations/022_pessoas.sql`.
- Cursos aceitos, exatamente: `Ciência da Computação`, `Engenharia Mecânica`, `Engenharia Elétrica`.
- Status: `ativo`, `trainee`, `inativo` (Alumni deixa de existir). Alumni antigo → `inativo` com `motivo_saida = 'Alumni'`.
- Motivo da saída: obrigatório ao **mudar para** Inativo (400 `MOTIVO_SAIDA_OBRIGATORIO`), até 500 caracteres (400 `MOTIVO_SAIDA_LONGO`). Voltar a Ativo apaga motivo e data de saída. Inativo sem motivo aparece como "Não informado".
- `fim_trainee`: gravado com `hoje()` quando o status muda de Trainee para Ativo; não antes de `data_entrada`, não no futuro; só a gestão edita (`PUT /usuarios/:codigo`), a própria pessoa não.
- E-mail pessoal: opcional, até 254 caracteres, formato de e-mail (400 `EMAIL_PESSOAL_INVALIDO`), visível para todos; editam a pessoa (`PUT /auth/perfil`) e a gestão.
- Telefone: máscara `(00) 00000-0000` (11 dígitos) e `(00) 0000-0000` (10 dígitos). O back confere só quando o campo muda: 10 ou 11 dígitos ignorando a pontuação (400 `TELEFONE_INVALIDO`); grava o texto como veio.
- Regra nova só vale quando o campo muda (lição da 24b): editar outro campo de quem tem curso/telefone antigo fora da regra continua funcionando.
- Erros: 400 dizendo o campo, mensagens em `source/shared/erros/mensagensDeErro.ts` (bloco `USUARIO`).
- Telas: visual Halo, claro e escuro, 375 px; responsivo só em `src/styles/responsive.css`.
- Commits em português, Conventional Commits, escopo `pessoas` (ou `ui`, `projetos` no bug); `npm run lint && npm run format:check` sem pipe antes de cada commit; rodapé de coautoria do Claude Opus 5.5 (conferir que nenhum commit sai com "Sonnet").
